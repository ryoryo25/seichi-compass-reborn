# 聖地コンパス Reborn (Seichi Compass Reborn)

「推しの聖地・ロケ地巡りに宝探しゲームのワクワクを」—— 2024年の **聖地コンパス** を、**TypeScript モノレポ（Next.js + Hono RPC + Drizzle/PostGIS + 将来 Expo モバイル拡張）** で再設計したリメイク版プロトタイプです。

初期ターゲットは **日向坂46**（「日向坂46 聖地一覧」Googleマイマップをベースにした約4,500件のシーンデータを構造化・近接スポット自動統合して収録）。

## 主な機能（プロトタイプ実装済み）
- **周辺聖地探索 ＆ コンパス案内**: 虫食いタイトルと距離・方位コンパスだけで現地を探す宝探し体験（端末リアルGPS/磁気センサー ＋ PC検証用デモ位置シミュレーター搭載）
- **探索者が調整できる難易度設定**: タイトルの虫食い度（イージー / ノーマル / ハード / ノーヒント）と到着前の表示タグ量を自由に設定可能（スポットIDシード固定によりリロードしても文字が漏れない設計）
- **到着判定（50〜180m）＆ ギブアップ救済**: 現地到着で「達成（＋コンパス自力発見バッジ）」、近づけない場所では「ギブアップ閲覧（未達成扱い）」に対応
- **聖地マップ（宝探しレーダー ＆ 通常マップ融合）**: 達成ピン＋未発見エリアのぼかし円表示と、全ピン表示の通常聖地マップをワンタップ切替（`<SeichiMap />` アダプタにより将来 Google Maps SDK へ容易に差替可能）
- **自分専用の非公開巡礼アルバム ＋ ひとことコメント**: 写真は他ユーザーに一切公開されないマイアルバムに圧縮保存し、到着者同士のテキストコメント・実績公開ON/OFFに対応
- **聖地・エピソード追加（二重登録防止）**: GoogleマップURL座標解析、ミニマップ上でのピンドラッグ微調整、半径60m以内の既存スポット検知による「エピソード追記」提案
- **管理者一括インポート**: Googleマイマップ KML および CSV の構造化インポート（メンバー名自動タギング・近接同名スポット自動マージ）

## セットアップ ＆ 起動方法

```bash
# 依存パッケージのインストール
npm install

# 開発サーバー起動 (http://localhost:3000)
npm run dev
```

※ `data/hinatazaka-mymap.kml` から初期シードJSON（`packages/db/seed/hinatazaka-spots.json`）を再生成する場合：
```bash
npm run seed:kml
```

詳細なシステム構成・本番インフラ設計（Cloudflare Workers + Neon PostGIS + Better Auth + Cloudflare R2 + Expo）は [docs/ARCHITECTURE.md](./docs/ARCHITECTURE.md) を参照してください。
